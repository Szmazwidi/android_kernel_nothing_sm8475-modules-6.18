# CLG11 ports (CLG283 development cohort)

Three further platform ports by Claude (2 Nov 2026), built and signed as a 283-module
development cohort (277 CLG277 modules + 6) and run on the development phone. They are
source-only here: the top-level `pong_modules` graph and `build-reference-6.18.60-CLG277.json`
are unchanged and still match the CLG277 prebuilt in `device/nothing/Pong-kernel`.

| Package | Module | Status on the development phone |
|---|---|---|
| `pmCLG11` | `qcom_stats.ko` (upstream, qcom,rpmh-stats) | works: subsystem/DDR/CX sleep counters in debugfs |
| `pmCLG11` | `subsystem_sleep_stats.ko` | works (`/dev/stats`); no DDR residency (no vendor soc_sleep_stats) |
| `pmCLG11` | `smp2p_sleepstate.ko` | loads; signals AP sleep state to the remote processors |
| `pmCLG11` | `qcom_cpuss_sleep_stats.ko` | probe -EINVAL: `qcom_scm_io_readl` is refused; debug only |
| `memshareCLG11` | `memshare.ko` | works: the modem requests 5 MB for client 1 (GNSS) at boot and gets it |
| `usbcCLG11` | `ucsi_glink_qti.ko` | **not working, not loaded**: firmware never completes the PPM reset |

`ucsi_glink_qti` is the upstream 6.18 `ucsi_glink` adapted to the vendor `qti_pmic_glink`
client API (same ADSP protocol as the Nothing 5.10 driver). v2 fixes a use-after-free in
remove() and retries registration on the glink UP event, but `ucsi_reset_ppm()` then waits for
CCI indefinitely, so the module is kept out of `modules.load`. Next step: compare the 5.10
UCSI core + vendor ucsi_glink init sequence with 6.18. `altmode-glink` and `fsa4480` are not
ported yet.
